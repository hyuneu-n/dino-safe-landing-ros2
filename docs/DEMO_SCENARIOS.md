# 참여형 장애물 회피·착륙 시연 구성

2026-09-14. 현재 코드와 맵에 근거한 시연 후보 및 구현 기준. **아래 장소는 환경·센서 검증을 마친 후보이며, 종단 간 비행 성공을 확인한 코스가 아니다.**

## 작품에서 보여줄 흐름

관람객이 목적지 선택 → 카메라로 진행 방향의 장애물 확인 → 감속·정지·우회 → 목적지 주변 스캔 → 점유된 좌표 대신 빈 공간 선택 → 하강 중에도 재평가 → 착륙 또는 안전한 대기.

목적지와 자기 위치는 항법 입력으로 사용하되, 장애물의 실제 좌표·정답 안전점은 회피/착륙 알고리즘에 전달하지 않는다. 현재 자기 위치는 Gazebo odom을 사용하므로 위치 추정까지 포함한 완전한 비전 전용 항법은 아니다. 현재 연구·시연 범위는 **RGB-D 기반 장애물 판단과 안전 착륙점 선정**이다. 위치 추정까지 카메라만으로 처리하려면 VIO/SLAM은 별도 작업이다.

## 현재 구현과 보강할 부분

| 항목 | 현재 | 시연을 위한 보강 |
|---|---|---|
| 목적지 선택 | 이륙 전·이륙 중·순항 중 `/clicked_point` 수신 | 명시적 대기/출발과 착륙 후 반복 배송 |
| 이동 중 회피 | 전방 depth를 좌·중·우로 나누어 여유가 큰 쪽으로 이동 | 장애물 앞 감속·정지, 이동 가능한 경로 평가, 막힘 탈출 및 재탐색 |
| 착륙점 탐색 | DINOv2 특징 군집 + depth, 후보 표시 | 후보점이 실제 안전 마스크 안인지 검증, 프레임 최신성·안정성 확인 |
| 동적 개입 | 하강 고도에 맞춰 보행자가 진입하는 자동 데모 | 관람객의 버튼으로 개입, 목적지 주변에서 자연스러운 보행 속도로 출발 |
| 후보 없음 | 이전 목표 유지 또는 지정 좌표로 착륙하는 대체 동작이 남음 | 하강 중지·호버·재탐색, 시간 초과 시 미션 중단 |
| 높이 변화 | 고정 순항/스캔 고도, 지면 z=0 가정 | 실제 표면까지의 거리와 자세를 반영한 좌표 변환·고도 제어 |
| 이동 모델 | `set_entity_state`로 위치를 지정하는 운동학적 제어 | 실제 상태와 명령 구분, 접촉/관통 여부를 별도 평가; 비행 동역학 검증은 별도 |

확인한 코드: `mission_controller.py`의 `compute_avoid_offset`, `on_click_point`, `SCAN`/`DESCEND`; `landing_detector.py`의 `process`, `pixel_to_world`, `_connected_components`.

현재 연결요소의 평균 좌표를 후보로 사용하므로, 가운데 장애물이 있는 고리 모양 안전 영역에서는 평균 좌표가 장애물 위에 놓일 수 있다. 후보는 실제 안전 영역 안에서 드론 크기만큼의 여유를 확보한 픽셀로 선택해야 한다. 또한 탐지기는 현재 yaw=0·지면 z=0을 가정한다. 도착 후 수평 스캔을 넘어 회전·경사·높이 변화가 있는 시연으로 확장할 때 이 가정을 먼저 정리해야 한다.

## 관람객에게 보일 화면

- 지도: 선택한 목적지, 실제 이동 궤적, 현재 드론 위치.
- 전방 카메라: 장애물에 따른 감속·정지·우회 방향. 지상 차량을 피하는 것처럼 연출하지 말고 실제 비행 높이에서 막히는 장애물을 사용.
- 하강 카메라: 요청 좌표, 제외 영역, 후보 안전 영역, 최종 착륙점.
- 상태: 이동 / 장애물 앞 대기 / 우회 / 스캔 / 하강 / 재탐색 / 착륙 / 착륙 보류.

가장 설득력 있는 비교는 같은 목적지에서 **개입 전에는 착륙하고, 사람이 들어오면 멈추거나 다른 곳을 선택하는 것**이다. 개입 버튼은 환경만 바꾸며 판단 결과를 미리 지정하지 않는다. 장애물이 늘어 안전한 공간이 사라졌다면 대기도 올바른 결과로 표시한다.

## 구현 순서와 통과 기준

1. **짧은 접근 + 정적 착륙**: 물류 야드에서 시작. 후보 없음에 대한 하강 금지, 안전 영역 안 후보 선택, 센서 최신성 확인을 먼저 구현한다.
2. **동적 재평가**: 광장에서 사람이 진입했을 때 하강을 멈추고 빈 곳을 재선택하거나 기다리는지 반복 검증한다.
3. **이동 중 회피**: 도심의 짧고 실제로 막힌 접근 코스부터 검증한다. 근처 구간을 통과한 결과를 임의 목적지 전체 항법 성공으로 확대 해석하지 않는다.
4. **대시보드와 반복 배송**: 검증한 목적지를 선택지로 제공하고, 새 목적지·개입 조건을 기록한다.
5. **복층·산악 확장**: 표면 고도와 상부 장애물, 좌표 변환을 처리한 뒤 높은 목적지를 활성화한다.

평가에서는 실제 장애물 배치/접촉 정보를 사용할 수 있지만 제어기에는 전달하지 않는다. 성공 여부는 착륙 로그만으로 정하지 않고, 실제 최종 위치·장애물 접촉 또는 관통·최소 여유·시간 초과·개입 시 반응을 함께 기록한다. 실패와 착륙 보류도 결과에 포함한다.

## Gazebo의 움직이는 사람

Gazebo Classic의 `actor`는 걷는 골격 애니메이션과 경로 이동을 결합할 수 있다. 왕복·순환 보행과 정지/재출발을 구현할 수 있으며, 플러그인 제어로 사용자 개입 버튼과 연결할 수 있다. 공식 문서는 actor가 RGB 카메라와 GPU 기반 depth 센서에 보인다고 설명한다. 실제 사용할 스킨과 이 프로젝트의 depth 카메라 조합은 별도로 캡처해 검증한다.

actor는 일반 동적 물체처럼 중력과 접촉력에 반응하지 않는다. 따라서 걷는 모습만 추가하고 물리적 충돌 평가가 끝났다고 취급하지 않는다. 별도의 충돌 프록시 또는 평가 전용 거리/교차 판정으로 사람과 드론의 간섭을 확인하고, 그 정답 정보를 제어 입력으로 넘기지 않는다.

출처: [Gazebo Classic — Make an animated model (actor)](https://classic.gazebosim.org/tutorials?cat=build_robot&tut=actor).

보행자는 두 종류로 구성한다.

- 배경 보행: 인도·광장 주변을 왕복/순환. 드론의 상태와 무관하게 움직여 살아 있는 환경을 만든다.
- 개입 보행: 관람객이 버튼을 누르면 착륙 영역을 가로지르고 빠져나간다. 드론은 이벤트 신호 대신 실제 카메라 변화를 보고 반응한다.

## 일반인용 대시보드 우선 구성

| 화면 요소 | 보여줄 정보 | 관람객이 이해할 점 |
|---|---|---|
| 목적지 카드 + 작은 지도 | 장소 사진·이름, 배송 요청, 현재 위치와 궤적 | 내가 고른 곳으로 이동한다 |
| 큰 전방 카메라 | RGB 위 장애물 영역·진행/회피 방향, 감속/정지 상태 | 앞을 보고 움직임을 바꾼다 |
| 큰 하강 카메라 | 요청 좌표와 최종 선택점을 다른 표식으로 표시, 제외 영역·후보 영역 | 목적지 좌표에 그대로 내리지 않고 빈 곳을 찾는다 |
| 한 문장 상태 설명 | 전방 장애물로 정지 / 착륙 구역 점유로 대기 / 다른 공간 재탐색 | 동작과 판단 이유를 연결한다 |
| 개입 버튼 | 사람 지나가기 / 차량 진입 / 장애물 추가 / 초기화 | 미리 정해진 영상이 아니라 상황 변화에 반응한다 |
| 결과 카드 | 요청점과 착륙점의 거리, 실제 접촉 여부, 대기·재선택 횟수 | 어떤 결과가 나왔는지 확인한다 |

기본 화면에는 RGB와 읽기 쉬운 표식을 크게 둔다. depth 영상, DINO PCA, 후보 점수, 프레임 시간은 접을 수 있는 기술 상세 화면에 둔다. 현재 DINO 군집은 사람/차량의 이름을 분류하는 객체 검출기가 아니므로, 구현하지 않은 '사람 인식' 라벨이나 보정되지 않은 '안전 확률 99%'를 표시하지 않는다. 현재 계산한 장애물/제외 영역과 실제 제어 상태를 표시한다.

가장 짧은 대표 시연: **물류 야드 선택 → 지정 좌표의 화물 확인 → 옆의 빈 공간 선택 → 관람객이 사람 진입 버튼 → 하강 중지 → 사람이 지나가면 재확인 후 착륙.** 이 흐름은 목표 시연이며, 현재 완성된 동작으로 문서화하지 않는다.

## 생활 목적지 추가

현재 환경에는 SkyDrop 물류창고 출발점 `(-210,-88)`, 맥도날드 `(172,68)`, 써브웨이 `(80,-104)`, 서경대 모티브 캠퍼스 `(340,330,z=12)`가 있다. 관람객에게는 “창고에서 출발 → 햄버거 가게 / 샌드위치 가게 / 학교 선택 → 현장 장애물 확인 → 착륙”으로 설명할 수 있다. 캠퍼스 배송은 고도 처리 수정 후 시연하며, 반복 배송·귀환·목적지 선택 대시보드는 아직 구현하지 않았다.
