# 2026-09-23 체크포인트 — 교수 피드백과 경로 생성 전환

이 문서는 2026-09-18 종합설계 발표와 이후 대화까지의 상태를 고정한다. 다음 작업에서 계획을 구현 완료로 오인하거나, 기존 환경 제작을 다시 시작하지 않기 위한 체크포인트다.

## 사용자 결정

- 현재 도시·공장·마을·강·고가도로·산동네·서경대 캠퍼스를 포함한 맵 제작은 종료한다.
- 다음 최우선 과제는 **전방 비전으로 장애물 영역을 해석하고 다음 이동 좌표를 생성하는 지역 경로 계획기**다.
- 지도교수 피드백을 반영해 결과만 시연하지 않고 `데이터 → 해석 → 시각화 → 판단 → 평가`의 근거를 제시한다.
- 1·2·3스텝 계획 horizon을 비교하고, 측정 결과로 최종 horizon과 파라미터를 결정한다.
- 전체 지도와 정답 장애물 좌표를 런타임 경로 계획기에 직접 제공하지 않는다. Gazebo odometry는 현재 위치 입력으로 사용하되, 장애물 판단은 전방 RGB-D를 사용한다.

## 구현 직전 기준선

### 순항

- `mission_controller.py`가 미리 생성된 manifest waypoint를 따라 이동한다.
- RViz에서 목적지를 클릭하면 미리 생성된 경로를 버리고 현재 위치와 클릭 지점을 잇는 직행 경로로 바꾼다.
- 전방 Depth를 좌·중·우 세 영역으로 나누고 각 영역의 5 percentile 거리를 계산한다.
- 중앙 거리가 22m보다 작으면 더 넓은 쪽으로 최대 9m의 측면 오프셋을 준다.
- 장애물이 사라지면 오프셋을 감쇠해 기준 경로로 돌아온다.
- 이것은 **반응형 회피 규칙**이다. 장애물 주변의 waypoint 열이나 다중 스텝 경로를 생성하지 않는다.
- 순항 회피에는 현재 **DINOv2가 사용되지 않는다**. 전방 Depth만 사용한다.

### 착륙

- 하방 RGB에서 DINOv2 ViT-S/14 패치 특징을 추출하고 K-means로 비슷한 표면을 묶는다.
- 하방 Depth로 높이 차이와 평탄도를 계산해 장애물·안전 영역을 만든다.
- 1m 안전 반경이 들어가는 후보를 점수화해 하나의 착륙 목표 좌표를 발행한다.
- 하강 중 새 목표가 0.7m 이상 이동하면 착륙점을 다시 정렬한다.
- 정지 장면 24개 평가와 새 대도시 전체 배송 성공률은 서로 다른 검증이다. 대도시 종단 간 비행 성공률은 아직 측정하지 않았다.

## 교수 피드백으로 확인됐던 공백

1. 장애물 감지 후 어느 좌표로 이동할지 생성하는 명시적인 경로 알고리즘이 없다.
2. 회피가 끝난 뒤 목적지 방향으로 어떻게 복귀하는지 비용과 제약으로 설명되지 않는다.
3. DINO의 출력, 장애물 표현, 계획기 입력, 드론 명령의 연결이 분명하지 않다.
4. 한 번의 좌우 반응과 1·2·3스텝 예측 계획의 성능 비교가 없다.
5. 판단 근거를 볼 수 있는 장애물 지도·후보 경로·선택 비용 시각화가 없다.

## 구현 완료 갱신 — 2026-09-23

이 체크포인트 작성 직후 Depth-only 기준 구조를 실제 구현했다. `local_path_planner.py`, `mission_controller.py` 통합, RViz 비용 지도·후보 경로, JSONL 로그, Gazebo 회랑 평가 도구가 추가됐다. H1/H2/H3 각1회 예비 비교에서는 H2만 목표10m 이내에 도달했다. 상세 결과는 [구현 기록](PATH_PLANNING_IMPLEMENTATION_20260923.md)을 따른다. DINO 순항 결합과 반복 실험은 아직 남았다.

## 구현의 기준 구조

```text
전방 RGB ── DINO 패치 특징 ─┐
                            ├─ 장애물/이동 가능/미확인 지역 비용 지도
전방 Depth ─ 거리·3D 투영 ──┘
                                      │
현재 자세·최종 목적지 ────────────────┤
                                      ▼
                         1·2·3스텝 후보 경로 생성
                                      │
                   충돌·여유·진척·회전·미확인 비용 평가
                                      ▼
                              최적 경로 선택
                                      │
                         첫 번째 지역 목표만 실행
                                      │
                         다음 프레임에서 다시 계획
```

상세 설계와 평가 계획은 [PROFESSOR_FEEDBACK_AND_PATH_PLANNING.md](PROFESSOR_FEEDBACK_AND_PATH_PLANNING.md)를 따른다.

## 갱신된 다음 작업 순서

1. H1/H2/H3 각1회 예비 실험을 여러 seed와 초기조건으로 반복한다.
2. 기존 `compute_avoid_offset()` legacy 모드를 같은 회랑에서 측정한다.
3. 목표 이탈, 지속 NO_PATH, 센서 중단을 실패 유형으로 집계한다.
4. 전방 DINO 특징을 비용 지도에 결합한다.
5. Depth-only와 DINO+Depth를 같은 조건으로 비교해 DINO 유지 여부를 결정한다.
6. 반복 근거로 horizon과 비용 가중치를 다시 선정한다.

## 완료 조건

- 장애물이 없으면 목적지 방향으로 안정적으로 전진한다.
- 장애물이 있으면 충돌하지 않는 지역 목표 좌표를 생성한다.
- 센서가 없거나 후보가 없으면 전진하지 않고 정지한다.
- 매 계획 주기의 입력, 후보, 비용, 선택 결과를 재현 가능한 형식으로 기록한다.
- 1·2·3스텝과 기존 좌·중·우 기준선의 성공률, 최소 여유, 경로 길이, 계획 시간을 같은 조건에서 비교한다.
- 선택한 horizon과 가중치를 “여러 번 해보니 괜찮았다”가 아니라 측정 결과로 설명할 수 있다.
