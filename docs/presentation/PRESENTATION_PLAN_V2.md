# 종합설계 발표 V2 — 내용 구성

기준일: 2026-09-16  
목적: 새 지도교수님이 프로젝트를 처음 듣는 상황에서, **무엇을 만들고 있는지 → 어떤 기술을 어디까지 구현했는지 → 어떤 환경에서 검증할지 → 최종 졸업작품은 어떤 경험인지 → 앞으로 무엇을 기술적으로 완성할지**를 이해시키는 발표.

기존 발표의 문제는 환경 이미지가 발표의 주인공처럼 보였다는 점이다. V2에서 맵은 기술을 시험하는 수단이며, 발표의 중심은 RGB-D 착륙 판단과 통합 시연 계획이다. 환경 투어 영상은 사용하지 않는다.

## 발표의 한 문장

> 배송 좌표에 바로 내리는 드론이 아니라, 목적지 주변을 RGB-D로 보고 장애물을 피해 안전한 빈 공간을 선택하는 배송 드론 시뮬레이션을 만든다.

## 슬라이드별 구성

### 01. 표지

- 제목: `RGB-D 기반 배송 드론 안전 착륙 시스템`
- 부제: `목적지 선택부터 장애물 회피·안전 착륙까지의 참여형 시뮬레이션`
- 발표자 이름은 `[이름 입력]`으로 남긴다.

### 02. 발표의 출발점

- 목적지 좌표는 “어디로 갈지”만 알려준다.
- 실제 도착 지점에는 사람·차량·화물이 있을 수 있다.
- 해결하려는 질문: `드론이 현재 장면을 보고 어디에 내려야 하는가?`

### 03. PART 1 — 내가 하고자 하는 것

파트 구분 슬라이드.

### 04. 문제 정의

- 입력: 배송 목적지 좌표 + 드론 카메라 RGB/depth.
- 출력: 안전 착륙점 또는 착륙 보류.
- 목표: 지정 좌표에 고집하지 않고 주변 안전 공간을 선택.

### 05. 프로젝트 범위

- 포함: RGB-D 장애물 판단, 착륙 후보 선택, 시뮬레이션 미션, 시각화.
- 현재 위치는 Gazebo odom 사용.
- 현재 드론 이동은 `set_entity_state` 기반 운동학적 제어.
- VIO/SLAM, 실제 비행 동역학, 실기체 제어는 현재 범위와 분리.

### 06. PART 2 — 기술 스택과 구현 상태

파트 구분 슬라이드.

### 07. 기술 스택과 역할

- ROS 2 Humble: 센서·탐지·미션 노드와 토픽 연결.
- Gazebo Classic 11: 도시, RGB/depth 카메라, 드론, 장애물.
- Python + NumPy/Pillow: 영상·마스크·좌표 처리.
- PyTorch + DINOv2 ViT-S/14: 14×14 패치, 384차원 특징.
- RViz2: 후보·선택점·카메라·포인트클라우드 시각화.
- COLLADA/SDF 절차생성: 재현 가능한 도시와 충돌 지오메트리.

### 08. 전체 기술 구조

- 하강 RGB/depth/odom → `landing_detector.py` → `/landing/target`.
- 전방 depth + waypoint → `mission_controller.py`.
- Gazebo의 드론 위치 제어와 RViz 출력.
- 착륙 판단과 이동 중 회피가 서로 다른 처리임을 명확히 표시.

### 09. 착륙점 판단 알고리즘 — 상세

1. RGB를 448×448로 입력, DINOv2 패치 특징 추출.
2. 특징을 K-means `k=5`로 무라벨 표면 군집.
3. depth 중앙값으로 지면 거리 추정, 0.45m 이상 솟은 패치를 장애물 처리.
4. 평평한 군집 중 주 표면과 색이 비슷한 영역을 안전 후보로 구성.
5. 드론 footprint 1.0m만큼 마스크 침식.
6. 연결요소 후보에 목적지 근접·평탄도·여유·면적 점수를 합산.
7. 최고 점수를 world 좌표로 변환해 발행.

주의: DINO 군집은 사람/자동차의 이름을 붙이는 객체 검출이 아니다.

### 10. 미션·회피·동적 재평가 — 현재 구현

- 상태: `TAKEOFF → CRUISE → ARRIVE → SCAN → DESCEND → LANDED`.
- manifest waypoint를 따라 이동.
- 전방 depth 좌/중/우 3영역의 여유를 비교해 측면 회피.
- SCAN 8초 동안 받은 선택점의 중앙값으로 1차 착륙점 확정.
- 하강 중 새 선택점이 0.7m 이상 이동하면 착륙점 재정렬.
- 데모용 사람이 착륙점으로 이동하는 이벤트 존재.

### 11. 어디까지 됐는가 — 구현과 검증을 분리

- 환경: 완료. 배치·RGB/depth 검사 통과.
- 착륙 판단: 구현. 후보·선택점·오버레이 출력.
- 기본 미션: 구현. 새 도시 전체 코스 성공률은 미측정.
- 전방 회피: 반응형 프로토타입. 정지·막힘 탈출·전역 재탐색 미완성.
- 동적 장애물: 자동 이벤트. 자연스러운 보행·버튼 제어 미완성.
- 대시보드·반복 배송: 설계 단계.

### 12. 이전 착륙점 선택 평가

- 이전 단일 회랑의 정지 RGB/depth 24장.
- 동일 장면·동일 GT·동일 footprint 판정.
- DINOv2+depth: 22/24.
- depth-only 재구현: 17/24.
- OpenLander RGB-only: 11/24, 후보 제시는 20/24.
- 이 결과는 새 도시의 비행 성공률이 아님을 명시.

### 13. PART 3 — 현재 맵

파트 구분 슬라이드.

### 14. 전체 환경 캡처

- 영상 없이 실제 Gazebo 캡처 4장.
- 도심·산업지구·고가도로/강·산동네.
- 텍스트는 “무엇이 있는가”보다 “어떤 시험 조건인가”에 집중.

### 15. 배송 목적지와 착륙 조건

- 물류창고 출발점, 맥도날드/써브웨이, 서경대학교, 물류 야드.
- 총 22개 목적지, 지정 위치가 점유된 시나리오 4개.
- 높이 12/34/36/96m 목적지 4개는 고도 처리 보강 후 자동 비행.

### 16. PART 4 — 최종 졸업작품 시나리오

파트 구분 슬라이드.

### 17. 관람객 경험의 전체 흐름

1. 지도/장소 카드에서 목적지 선택.
2. 물류창고에서 배송 시작.
3. 이동 중 전방 카메라로 장애물 판단.
4. 목적지 상공에서 하강 카메라 스캔.
5. 요청 좌표 대신 안전한 빈 공간 선택.
6. 사람이 들어오면 정지·재탐색·재선택.
7. 착륙 또는 안전 대기 결과 표시.

### 18. 최종 화면 구성

- 왼쪽: 지도, 목적지 카드, 실제 이동 궤적.
- 중앙: 전방/하강 카메라, 장애물·안전 영역·선택점.
- 오른쪽: 미션 상태와 판단 이유.
- 하단: 배송 시작, 사람 지나가기, 장애물 추가, 초기화.
- 기술 상세 탭: depth, DINO PCA, 처리 시간.

직접 조종 게임보다 “드론에게 배송을 맡기고 상황을 바꾸는 관제 체험”으로 정의한다.

### 19. 대표 시연 시나리오

- 출발: SkyDrop 물류창고.
- 목적지: Foundry Yard 또는 Civic Plaza.
- 1차 판단: 지정 좌표의 화물/사람을 피해 빈 공간 선택.
- 관람객 개입: 하강 중 사람 진입.
- 기대 동작: 하강 중지 → 재탐색 → 다른 곳 선택 또는 대기.
- 결과 카드: 접촉 여부, 요청점과 착륙점 거리, 재선택 횟수.

### 20. PART 5 — 기술 발전

파트 구분 슬라이드.

### 21. 기술 우선순위와 통과 기준

1. 후보 없음 → 하강 금지, hover/retry/abort.
2. 후보점 → 실제 안전 마스크 내부와 footprint 여유 확인.
3. z/yaw → 카메라 자세와 목적지 표면 고도 반영.
4. 이동 회피 → 감속·정지·막힘 탈출과 경로 복구.
5. 평가 → 접촉/관통·최소 여유·시간·대기/실패까지 기록.
6. 통합 → 목적지 선택·사람 개입·반복 배송 대시보드.

### 22. 개발 순서

- 단계 1: 짧은 접근 + 정적 장애물 착륙.
- 단계 2: 사람 진입 + 안전 정지/재선택.
- 단계 3: 실제로 막힌 구간의 이동 회피.
- 단계 4: 목적지 선택·반복 배송 UI.
- 단계 5: 캠퍼스·교량·산동네의 높이 있는 목적지.

각 단계는 기능 구현이 아니라 반복 성공 조건을 통과해야 다음으로 이동한다.

### 23. 결론

- 지금까지: 다양한 시험 환경, RGB-D 착륙 판단, 기본 미션과 시각화 확보.
- 이제부터: 맵 확장이 아니라 안전 실패 처리와 통합 신뢰성 검증.
- 다음 회의 질문: 첫 시연 코스를 어디로 정하고, “성공”을 어떤 지표로 정의할 것인가?

## 발표에서 피할 표현

- “완전한 비전 자율비행” → 위치는 Gazebo odom을 사용한다.
- “도시 전체 배송 성공률 92%” → 22/24는 이전 정지 장면의 착륙점 선택 결과다.
- “사람을 인식한다” → 현재는 클래스 분류가 아니라 표면/장애물 영역을 판단한다.
- “맵의 모든 목적지가 비행 가능하다” → 높이 있는 4개 목적지는 제어 보강 전이다.
- “대시보드가 완성됐다” → 최종 결과물의 설계이며 아직 미구현이다.
