## 시연 전에 먼저 보강할 것

1. **안전 후보가 없으면 내리지 않기.** 현재 `mission_controller.py`의 SCAN은 탐지가 없으면 목적지 좌표로 하강한다. 후보 없음/오래된 센서에는 대기·재탐색·중단을 구현해야 한다.
2. **후보가 실제 안전 영역 안에 있는지 확인.** 연결요소 평균점은 고리형 영역의 장애물 위에 놓일 수 있다. 드론 크기만큼 여유가 있는 픽셀에서 선택해야 한다.
3. **높이와 회전 처리.** 탐지 좌표 변환은 yaw=0·지면 z=0을 가정한다. 캠퍼스/교량/산동네의 표면 고도와 카메라 자세를 처리해야 한다.
4. **지역 계획 반복 검증.** 막힘·센서 끊김 정지는 구현했다. 여러 배치에서 목표 이탈·NO_PATH 지속과 재관측 복구를 반복 측정해야 한다.
5. **반복 실험.** 실제 도달 위치·장애물 접촉 또는 관통·최소 여유·재선택/대기·시간 초과를 기록한다. `LANDED` 로그만으로 성공을 판정하지 않는다.

현재는 Gazebo odom을 이용하고 `set_entity_state`로 위치를 직접 지정한다. 따라서 정확한 설명은 **“RGB-D로 장애물을 판단하고 안전 착륙점을 고르는 시뮬레이션”**이다. 위치 추정까지 비전만으로 하는 항법(VIO/SLAM)이나 비행 동역학/실기체 제어는 별도 범위다.

## 게임처럼 만들 것인가

**드론 배송을 맡기고 상황을 바꾸는 체험형 관제 화면**을 기본으로 한다. 관람객이 직접 조종하면 알고리즘의 자율 판단을 보여주기 어려우므로, 조작은 목적지와 환경 변화에 집중한다. 점수/시간 경쟁은 필수가 아니다. 안전한 곳이 없을 때 기다리는 것도 올바른 결과로 설명한다.

대표 흐름:

1. 장소 사진이 있는 카드에서 “물류 야드 / 햄버거 가게 / 광장” 선택.
2. “배송 시작” → 실제 전방 카메라와 이동 궤적 표시.
3. 도착하면 하강 카메라를 크게 표시. 요청한 위치와 실제 선택한 착륙점을 다른 표식으로 표시.
4. 관람객이 “사람 지나가기” 선택 → 환경의 사람만 움직인다. 제어기에 장애물 좌표나 정답 착륙점을 전달하지 않는다.
5. 알고리즘이 하강 중지·재선택·대기한 실제 상태를 한 문장으로 설명.
6. 결과 카드: 착륙/보류/실패, 요청점과 최종 위치, 대기·재선택 횟수, 접촉 여부. 이후 “다시 배송”.

화면은 지도/목적지 카드, 큰 카메라, 상태 설명, 개입 버튼, 결과 카드로 구성한다. RGB 위에 실제 제외 영역과 선택점을 표시하고, depth·DINO PCA·처리 시간은 “기술 보기”로 접는다. 구현하지 않은 사람/차량 분류나 근거 없는 안전 확률을 표시하지 않는다.

처음에는 **물류 야드의 짧은 접근과 착륙 → 광장의 사람 개입 → 도심 이동 중 회피 → 여러 목적지와 반복 배송 → 높은 캠퍼스/교량** 순서로 늘린다. UI를 게임처럼 꾸미는 것보다 이 한 사이클이 반복해서 신뢰성 있게 동작하는 것이 우선이다.

구체적인 장소·좌표·통과 기준은 [DEMO_SCENARIOS.md](DEMO_SCENARIOS.md)를 따른다. 이 문서의 대시보드와 보강 항목은 계획이며 아직 구현된 기능이 아니다.
