# Connected Metropolis — 도시 환경

2026-09-14. 현재 `run_city_demo.sh`가 기본으로 여는 월드.

뉴욕풍 고층 도심과 벽돌 상가 → 공장·물류 지구 → 저층 주거 타운을 하나의 도로망으로 연결했다. 약 2.5km × 1.9km 범위로 확장했으며, 강과 양쪽 강변, 고가도로·원형 램프·교량, 굽은 외곽 도로와 산동네까지 포함한다. 구역만 커지는 대신 **12m 하강 카메라에 서로 다른 표면과 장애물이 실제로 보이는 것**을 기준으로 목적지를 구성했다.

## 실행

```bash
# 환경만 둘러보기: 탐지기와 미션을 시작하지 않음
bash run_city_demo.sh 0 world

# 기존 탐지기·미션·RViz와 함께 실행
bash run_city_demo.sh 0

# RViz 없이 전체 미션
bash run_city_demo.sh 0 norviz
```

생성기만 실행:

```bash
python3 worlds/generate_metropolis.py --seed 0 --out /tmp/metropolis/city.world
```

`.world`, `.waypoints.json`, `city_assets/` COLLADA 메시 디렉터리가 함께 생성된다. 월드를 다른 위치/컴퓨터로 옮길 때에는 그곳에서 재생성한다(월드의 메시 경로는 절대 경로). 별도 에셋 다운로드 없이 Python 표준 라이브러리로 생성한다. 시드는 건물 높이·재질·주택 지붕을 바꾸고, 거리와 목적지 위치는 유지한다.

기존 `worlds/generate_city.py`는 이전 격자·맨해튼·마을 생성기로 보존했다. 기존 비교실험 결과도 이전 평가 환경의 수치이며, 새 도시에서의 성능 수치가 아니다.

## 시각 구성

- 도심: 유리 타워, 석재 랜드마크, 벽돌 중층 건물, 상가 차양, 창틀, 외부 비상계단, 옥상 설비, 횡단보도와 신호등.
- 산업: 창고·하역문·도크·채광창, 컨테이너, 트럭, 팔레트, 울타리, 굴뚝.
- 주거: 경사지붕 주택, 정원과 담장, 주차 차량, 마을 공원, 상점 주차장, 텃밭.
- 수변·공사: 산책로, 벤치와 수목, 난간, 수면, 비계, 낮은 건축자재.
- 고가 교통: 높이 24m 강변 고가도로, 높이 34m 사장교, 270도 연결 램프와 회전 진출로, 지상 접속부, 교각과 정적 차량.
- 산동네: 높이 94m까지 오르는 굽은 산길, 좁은 능선 골목, 도로 방향을 바라보는 주택과 경사지붕, 옹벽·테라스·숲.
- 외곽: 서쪽의 비격자 구시가지와 골목, 강 건너 저층 마을과 산책로.

시드 0 기준 건물 148동. 작은 창문·창틀 등을 각각 Gazebo 모델로 만들지 않고 건물별 COLLADA 메시로 묶는다. 건물 본체의 충돌 크기는 시각 메시와 같은 치수에서 생성한다. 나무 수관·경사지붕 등은 보수적인 박스 충돌 근사이며, 창문과 난간 일부는 시각 디테일이다. 정적 사람 모델과 기존 `person_intruder` 데모도 포함한다.

## 물류 출발지와 상점·캠퍼스

`worlds/metropolis_landmarks.py`에서 간판과 건물을 절차생성한다. 별도 로고 이미지 다운로드 없이 메시로 만든 간판이다. 서경대는 사용자 제공 사진 3장을 바탕으로 `worlds/metropolis_campus.py`에서 재구성했다. 원통형 유리 타워, 아치 강의동과 맨사드 지붕, 붉은 본관, 노란 포인트 외벽, 줄무늬 광장, 분수·계단 정원을 반영했다. 실제 학교의 측량 복원은 아니며 치수와 배치는 시뮬레이션에 맞췄다. 캠퍼스의 충돌은 시각 메시와 같은 메시를 사용한다.

| 새 목적지 ID | 좌표 x, y, z | 구성 |
|---|---|---|
| `launch_depot` | -210, -88, 0 | SkyDrop 물류창고, 하역문·트럭·화물, H 출발 패드 |
| `mcdonalds_delivery` | 172, 68, 0 | 빨간 간판·골든 아치·차량·야외 테이블 |
| `subway_delivery` | 80, -104, 0 | 도심 건물 1층 상점, 차양·테이블·골목 |

드론 SDF 초기 위치와 manifest의 `start_xy`를 물류창고로 맞췄다. 기본 `waypoints`는 창고 진입로에서 도심 대로를 거쳐 East Gate로 이어진다. `origin`과 `landmarks`도 manifest에 기록한다. 이는 출발 위치·경유점 설정 변경이며, 새 노선의 종단 간 비행 성공은 아직 검증하지 않았다.

## 검증 및 한계

```bash
python3 -m unittest discover -s eval -p test_metropolis.py
bash eval/validate_metropolis.sh /tmp/metropolis_validation
```

첫 검사는 시드 0·7·23의 건물 겹침, 모델 이름 중복, 메시 파일 참조, 대체 공간의 충돌 여부를 검사한다. 두 번째는 별도 Gazebo master/ROS domain에서 서버를 띄워 구역 전경 14장과 목적지 22곳의 RGB·depth를 캡처하고 서버를 종료한다. `review/sensor_report.json`에 유효 depth 비율과 깊이 범위를 저장하며, 시야에 장애물이 없어 깊이 변화가 거의 없는 경우 실패한다. 산길 5개 지점과 캠퍼스 진입로 3개 지점도 실제 하강 depth로 확인해 도로가 지형에 묻히는 회귀를 검사한다.

이번 환경 작업은 렌더링과 센서·배치 검증까지다. **새 도시에서 DINOv2의 성공률이나 22개 목적지의 비행·착륙 성공을 검증한 것은 아니다.** 기존 제어기는 순항 중 클릭 시 직행으로 바꾸며 전체 도시 도로망을 재탐색하지 않는다. 착륙 후 재출발도 별도 구현이 필요하다. **캠퍼스·교량·산동네의 높이가 있는 4곳은 환경과 카메라 검증용이다. 기존 고정 스캔·착륙 고도를 수정하기 전에는 자동 비행으로 보내면 안 된다.** 목적지 메타데이터에 `z`, `requires_elevation_support`, `flight_validated`를 기록하며, 새 고도별 자동 비행을 구현한 것으로 취급하지 않는다. 물은 정적 시각 표면으로, 유체 시뮬레이션은 아니다.

## 지형·도로 구현

`worlds/metropolis_region.py`가 지역 확장을 담당한다. 강 양쪽 지형은 삼각형 메시이며, 완만한 지형 법선으로 면의 경계를 부드럽게 표시한다. 도로는 3차원 중심선을 따라 이어진 상판으로 만들고, 지형은 도로·주택 테라스에 맞춰 절개한다. 지형과 도로의 충돌 메시가 시각 메시와 같은 파일을 참조한다. 기존 도심 평지는 고정해 외곽 지형 수정이 기존 목적지를 침범하지 않도록 했다.

`.waypoints.json`의 `roads3d`는 확장 구역 도로의 좌표·폭·고가 여부를 담는다. 기존 미션 제어기에 자동 경로계획을 연결한 것은 아니다. 모든 교통 차량은 현재 정적이다. 도로는 시연을 위한 절차생성 디자인이며 실재 올림픽대로의 측량 모델이 아니다.

## 다음 단계: 참여형 시연과 대시보드

환경 다음 순서로 진행할 후보이며, 아직 구현하지 않았다.

1. 구역 지도와 목적지 카드: 도심/공장/주거/수변을 골라 배송 요청, 해당 장소의 카메라로 전환.
2. 반복 배송: 착륙 후 새 목적지 선택·재이륙, 목적지의 높이와 경로를 일관되게 처리.
3. 장애물 개입: 사람 이동, 차량 추가, 팔레트 배치. 명령은 환경만 바꾸고 탐지기는 카메라로 변화 감지.
4. 상황 프리셋: 낮은 장애물/좁은 공간/움직이는 사람/표면 혼합을 선택해 비교.
5. 근거 표시: RGB·depth·안전 마스크, 후보점과 최종 선택점, 현재 비행 상태를 한 화면에 표시.
6. 재현: 시드·목적지·장애물 변경 이력과 결과를 저장해서 같은 조건을 다시 실행.

## 환경 소개 MP4

`bash eval/record_city_tour.sh artifacts/metropolis_tour --seconds 60 --fps 24`로 720p H.264 영상을 만든다. 촬영 월드에서는 배송 드론 센서를 전용 RGB 카메라 하나로 교체하고, 위치 설정 응답 이후 새 프레임을 받아 인코딩한다. 실제 렌더링이 느려져도 출력 프레임 간 경로 간격은 일정하다. MP4와 프레임별 위치/시선 JSON을 함께 저장한다. 소개 영상의 카메라 이동은 장애물 회피 제어와 무관하다.

검증 서버는 `VALIDATION_MASTER_URI`/`VALIDATION_ROS_DOMAIN_ID`, 영상 서버는 `TOUR_MASTER_URI`/`TOUR_ROS_DOMAIN_ID`로 지정한다. 일반 GUI의 `GAZEBO_MASTER_URI`를 상속해 잘못 접속하는 문제를 피하도록 별도 변수로 분리했다.
